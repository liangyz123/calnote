# 日历便签 v8.3 · 优化说明

这一版**不改功能、不改数据结构、不碰你的数据**，只做三件事：把慢的地方提上去、把已经存在的 bug 修掉、把默认行为和文档对齐。所有实测数据都是我在沙箱里按你的项目规模（5300 条内容 + 1500 个附件 + 750 条 NAS 引用 + 8000 张缩略图缓存）压出来的，测试脚本和库都在包外，需要可以再跑一遍给你看。

## 一、性能实测（同一台机器、同一份库，新旧代码各跑 4 次取最快）

| 位置 | 优化前 | 优化后 | 提升 |
| --- | --- | --- | --- |
| 日历整月 `GET /api/items?month=2026-10` | 45.8 ms | 9.5 ms | **4.8 倍** |
| 当天详情 `GET /api/day` | 38.9 ms | 5.3 ms | **7.4 倍** |
| 提醒 `GET /api/reminders` | 297.3 ms | 23.2 ms | **12.8 倍** |
| 农历整月 `GET /api/calendar-info` | 7.1 ms | 0.3 ms | **20.9 倍** |
| 搜索 `GET /api/items?q=…` | 13.0 ms | 11.0 ms | 1.2 倍 |
| 分类浏览 `GET /api/items?folder=1` | 13.9 ms | 8.7 ms | 1.6 倍 |
| 列目录 `GET /api/nas/ls`（600 项） | 16.2 ms | 15.0 ms | 持平 |
| 导出 `GET /api/export` | 81.8 ms | 84.7 ms | 持平 |
| 连续 5 张缩略图（缓存已到 8000 上限） | 500 ms | 5 ms | **约 100 倍** |
| 第一次打开「今天」（NAS 能上外网时） | 1013 ms | 6 ms | **约 170 倍** |
| 导入 4000 行 | 241 ms | 163 ms | 1.5 倍 |
| 同一份再导一遍（全部判重） | 218 ms | 102 ms | 2.1 倍 |

你的 NAS 是机械盘、CPU 比沙箱弱，绝对数值会比上表高；但越是走磁盘和农历换算的项（缩略图、提醒、整月农历、当天天气），在 NAS 上的收益会比沙箱更明显。

具体改了什么：

1. **附件/文件夹的逐条查询合并成整批三次查询**。原来每条内容都要单独查一次文件夹名、一次附件表，每个 NAS 引用还要再对附件表做一次全表 `COUNT(*)`。五十条内容就是上百次查询加几百次磁盘 stat。现在一页只查三次（`_Bundle` / `items_to_dicts`）。
2. **农历换算结果缓存**。`LunarMonth.fromYm` 单次实测约 1.4 ms，是本项目最贵的一步；而每年重复的生日/纪念日一次请求里要算两三遍（列表算一次、提醒里 `next_occurrence` 再算一次）。现在按 (农历年,月,日) 记住，单日农历/黄历按天缓存、整月日历按月缓存。
3. **缩略图缓存淘汰不再每生成一张就扫全目录**。原来是 `listdir` 整个 `data/thumbs` 再对每个文件 `getmtime` + `getsize`（上限 8000 张 ≈ 1.6 万次磁盘调用），照片墙一屏几十张就是几秒钟。现在攒够一批（默认 800 张）或超过 120 秒才真扫一次，淘汰也只排一次序、按需删。
4. **打开「今天」不再等联网取天气**。原来首次访问会同步请求 Open-Meteo，超时上限 8 秒，实测 1013 ms 全压在首屏。现在本次先回天气档案值，实测值交后台线程刷进库，下次进来就是新数据（响应里多带一个 `weather_updating: 1` 表示正在刷）。
5. **提醒接口先用 SQL 圈定候选**。原来把「除笔记外的全部条目」都捞出来逐条加工（测试库里 843 行），五千条库里这一发就是 297 ms。现在按类型 + 日期区间分四条走索引的查询取候选，实测候选降到 471 行（yearly 253 + 到期待办 218，日程/倒数日当天为零）。
6. **天气缓存落盘从「每取一天整写一遍」改成节流 30 秒 + 临时文件原子替换**，全量 JSON 写入次数下降一个数量级。

## 二、顺手修掉的 bug（这些是真 bug，不是优化）

1. **`/api/items?month=` 那条 return 没关数据库连接**。请求一多就是文件句柄泄漏，长期跑在 NAS 上迟早出问题。已补 `conn.close()`。
2. **同一个生日/纪念日在日历上会出现两次**。代码里收集了 `seen` 集合却从没用它过滤，主查询命中的 yearly 条目会被 `yearly_hits` 再加一遍。实测 2026-10 返回 56 条里有 3 条是重复的，现在 53 条、重复 0。
3. **NAS 浏览器「按时间 / 按大小」排序是失效的**。排序键要读 `mtime`，但列目录时压根没把这个字段塞进结果，永远取到 0；而且 `desc=1` 在这两种排序下被无条件 `reverse()` 覆盖，只能反向不能顺向。现在字段补齐、升降序按你点的来。
4. **天气缓存文件可能被写坏**。内存 dict 没有锁，请求线程和后台都可能改；落盘是 `open(path,"w")` 直接覆盖，写到一半断电或崩溃，档案文件就废了。现在加锁 + 写临时文件再 `os.replace`。
5. **月份格式错误的报错口径**。原来整段包在 `try/except ValueError` 里，装配数据时任何 ValueError 都会被打成「月份格式应为 YYYY-MM」，误导排查。现在解析格式和业务处理分开。
6. **默认值与文档不一致**：代码里 `RAIN_MIN_MM` 默认 0.1，README 和 compose 写的都是 0.5（「0.5mm 以下不算雨」）。本版统一成 0.5。**这条会改变行为**：不设该变量的裸机 `python app.py` 部署，判雨会比之前保守一些；想回到旧口径就设 `RAIN_MIN_MM=0.1`。
7. **清理了永远走不到的死代码**：`/api/stats` 里多余的 `conn2`、`day_info` 里 `source == "实时获取"` 的判断（该值从不存在）、提醒里没用上的 `now`。

## 三、健壮性与安全（默认不改变现有行为）

- **数据库并发**：统一开启 `busy_timeout=10000`、`synchronous=NORMAL`、`temp_store=MEMORY`，并在启动时把日志模式设为 **WAL**。NAS 机械盘 + FUSE 上「写天气、删缩略图、改条目」撞车是最容易报 `database is locked` 的场景，忙等 + WAL 正是针对它。⚠️ **如果 `data/` 挂在 NFS / SMB / CIFS 这类共享文件系统上，请把 `DB_WAL=0`**——WAL 在网络文件系统上不安全。本地卷、飞牛本机卷保持默认即可。
- **补了 4 个索引**（启动时自动建，旧库直接生效）：`items(folder_id)`、`items(type,date)`、`items(type,done,date)`、`attachments(kind,missing)`。
- **请求体上限**：`MAX_CONTENT_LENGTH=26MB`（附件本身限 20MB），超大文件不再先整份吃进临时区；超了返回 JSON 报错而不是半屏 HTML。
- **读接口不再写库**：`GET /api/attachments/<id>` 原来每次都要 `UPDATE ... size`，现在只有大小真的变了才写。
- **少泄露内部路径**：`/api/health` 不再返回数据库绝对路径，`/api/nas/pick` 和 `/api/nas/ls` 不再把容器内绝对路径回传前端（前端本来也没用这两个字段）。
### 账号密码防护（本版已启用）

原来的项目**没有任何身份验证**：谁能在网络上摸到这个 8000 端口，谁就能读、能改、能删你的全部笔记，还能借应用浏览 compose 里挂进来的 `资料/相片/制造分厂` 三个目录。README 又教你用 fnOS 的 https 域名从外网访问，所以这一版直接把口令登录做进去了，并在 `docker-compose.yml` 里**默认开启**。

包内已写入的初始账号（可以直接用，也可以按下面的方法换掉）：

```
账号：calnote
口令：<你的登录口令>
```

工作方式：

- 浏览器打开任意页面 → 自动跳到登录页（页内表单，手机上也好用），登录成功后回到你原来想看的那一页。
- 登录状态用签名 Cookie 保持，默认 **30 天免重新输入**（改 `AUTH_TTL_DAYS`）。iPhone「添加到主屏幕」的 PWA 同样适用——这点比弹窗式的基础认证稳，弹窗在 iOS 独立窗口里经常不 remember。
- Cookie 里带的是 `过期时间戳.签名`，签名由「账号+口令」派生的密钥算出，改动用 `hmac.compare_digest` 定长比较。**口令一改，所有人的登录状态立刻作废**，不用手工清理。
- 未登录时：页面请求 302 到登录页；`/api/` 请求返回 401 JSON。前端 `app.js` 里的 `api()` 已加了对应处理，会话过期会**自动带你回登录页**，而不是干巴巴弹一句「请求失败」。
- 脚本 / curl / 反代探活仍然可以继续用凭据方式：`curl -u calnote:<你的登录口令> http://NAS内网IP:8000/api/stats`。
- 容器健康检查 `/api/health` 不要求登录（否则 Docker 会把好端端的容器判成不健康反复重启）；静态资源（js/css/图标）也不拦，页面数据和接口全部在墙内。
- 走 https 域名访问时，把 compose 里 `AUTH_COOKIE_SECURE=1` 那行的注释去掉，Cookie 就只在加密连接里传。

换口令 / 关防护：改 `docker-compose.yml` 里 `AUTH_USER` / `AUTH_PASS` 两行，再 `docker compose up -d` 重建即可；想彻底回到无口令状态就把这两行注释掉。⚠️ 这个口令是明文放在 compose 里的（家庭 NAS 自用的常规做法），所以**不要复用它登录别的服务**，另外别把这个包分享出去。

已验证的行为清单（沙箱真实起服务 + 接口级断言，共 18 项）：未登录访问首页 302 到 `/login?next=/`、未登录取数据 401、`/api/health` 放行、静态资源放行、登录页可打开且带账号/口令输入框、口令错 401 且不下发登录态、口令对 302 且下发签名 Cookie、登录后数据与提醒接口 200、`/login?next=//evil.example.com` 这类外部跳转被拒绝（只认站内相对路径）、退出登录后重新变 401、篡改 Cookie 被拒、超过有效期的 Cookie 被拒、`-u` 正确口令 200 / 错误口令 401。
- **静态资源改成协商缓存**（`Cache-Control: no-cache` + ETag）：配合现有 sw.js 的网络优先策略，文件没变就 304 不重传，改了立即生效，不会读到过期前端。sw.js 缓存号已升到 `calnote-v8.3`。

## 四、payload 的三处细微变化（都已确认前端不依赖）

1. `/api/reminders` 每条不再带 `attachments` 明细（提醒弹层只显示标题、类型、剩余天数，一次请求省下几百次附件查询）。
2. NAS 引用的「🔗N 几个笔记在用同一文件」计数改为**只统计还在引用的条目**：做过「存一份」的副本（`kind` 已变 `upload`）不再计入，数字比以前更准。
3. 列目录时子目录的「多少项」最多数到 120，超过显示 `120+`（`app.js` 已同步改好，新增 `n_more` 字段）。这是为了避免在一个几万文件的大目录里点一下卡十几秒；想调上限改 `NAS_DIR_COUNT`，设 0 表示不数。

除此之外接口返回逐字段对齐旧版：我用新旧两份代码跑同一份库，对 21 个接口做了结构化 diff，除上述有意项外**全部一致**；`/api/export` 导出的 CSV **逐字节相同**（1542775 字节）。

## 五、怎么更新到 NAS

跟你原来的流程一样，一条命令（会自动备份数据库、失败自动回滚）：

```bash
cd /vol3/1000/01资料/calnote
sh update.sh calnote-v8.3.zip
```

- 只覆盖代码，`data/`（`calnote.db`、`attachments/`、`import/`、`thumbs/`、`weather_cache.json`）一律不动，**不需要重新导入数据**。
- 更新后第一次打开会先进登录页，用 `calnote` / `<你的登录口令>` 登录（登录后 30 天内不再问）。手机主屏幕图标同理，登录一次就记住了。
- 索引和 WAL 是启动时自动生效的，不用手工迁移。
- 手机重开一次「千问便签」即可（缓存号换到 v8.3）。
- 想更保守，可以先只把 `data/thumbs/` 整个删掉再重启——缩略图会自动重建，不影响原文件。
- 回滚：`update.sh` 自带 `data/calnote.db.bak-日期`，代码退回旧 `app.py` 再起一次容器就行（旧版没建过那 4 个索引，留着也不影响）。

## 六、新增可配环境变量

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `DB_WAL` | `1` | 数据库日志模式；`data/` 挂 NFS/SMB 时设 `0` |
| `DB_BUSY_MS` | `10000` | 拿不到写锁时的忙等毫秒 |
| `WEATHER_TIMEOUT` | `5` | 联网取天气的超时秒（原来是硬编码 8） |
| `WX_FLUSH_SEC` | `30` | 天气缓存攒多少秒整体落盘一次 |
| `RAIN_MIN_MM` | `0.5` | 多少毫米降水以上才算雨（本版对齐文档） |
| `THUMB_SWEEP_SEC` | `120` | 缩略图缓存目录最少隔多久扫一次 |
| `NAS_DIR_COUNT` | `120` | 列目录时子目录「多少项」的计数上限，`0` 为不统计 |
| `MAX_BODY_MB` | `26` | 单次请求体上限 |
| `AUTH_USER` / `AUTH_PASS` | 包内已设为 `calnote` / `<你的登录口令>` | 账号口令；两个都配了才启用，注释掉即关闭 |
| `AUTH_TTL_DAYS` | `30` | 登录状态保持天数 |
| `AUTH_COOKIE_SECURE` | 关 | 走 https 时设 `1`，Cookie 只在加密连接传输 |

## 七、我没动的地方（以及为什么）

- **仍然用 Flask 自带服务器**（`python app.py`）。单用户家庭 NAS 够用，换 gunicorn 要同时改 Dockerfile 和启动方式，收益对你不明显。真要多人并发访问再换。
- **前端 `app.js`（2220 行）没做结构重构**，只改了两处目录计数显示。它本身写得不错：已有 `esc()` 转义、搜索 450ms 防抖、`Promise.all` 并行拉月份和农历、图片 `loading="lazy"`；搜索高亮 `hl()` 是先转义再插 `<em>`，没有 XSS 口子。真要减负应该拆模块，那属于功能改造，风险和本版「不动行为」的目标冲突。
- **`tools/` 下五个脚本没优化**（都是一次性导入工具，跑完就完，不在热路径上）。
- **NAS 目录挂载校验只在读时做**，没加启动时的自检；如果你改 compose 挂载忘了改 `NAS_ROOTS`，现在仍是页面上报「没有可用的 NAS 目录」。要的话可以在启动时打印一次各来源的挂载状态。
