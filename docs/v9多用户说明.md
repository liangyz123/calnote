# 日历便签 v9 · 第 1 期：全家多用户

这一期把「一个人用的便签」变成「一家人共用、但各人有各人的隐私」。地基（账号体系与权限）先落地，记账和密码本建在它上面，所以顺序是先多用户、再记账、再密码本。

## 一、你现在有三个账号

| 账号 | 身份 | 口令在哪 |
| --- | --- | --- |
| `calnote` | 管理员（就是你） | **沿用你 v8.3 的那个口令，没变** |
| `jiaren1` | 成员 | 写在 `docker-compose.yml` 里 `AUTH_MEMBER_PASS` 那一行 |
| `jiaren2` | 成员 | 同上 |

两个成员账号是首次启动时自动建的。初始口令我不往聊天里贴（聊天端会把口令打成 `***`，而且凭据本来就不该留在对话里），它就在你 NAS 上的 `docker-compose.yml` 里，和 `AUTH_PASS` 挨着。把口令发给家人后，让他们登录后进「成员与口令」改成自己的——成员页顶部有个「改我的口令」按钮，改完只有他一个人需要重新登录。

再想加人就进「成员与口令」→「＋ 新成员」，不用改配置文件。

## 二、权限就一条规则

```
可见 = 自己的全部内容  +  别人的「非笔记且没标仅自己可见」内容
可改 = 同上
```

- **笔记**：严格私有。家人（包括你自己用管理员账号）看不到、改不了、删不掉别人的笔记；导出 CSV 也导不出别人的笔记正文。
- **日程 / 生日 / 纪念日 / 待办 / 倒数日**：全家共享，都能看到、都能帮忙改或删，提醒也是全家一起收。
- `items` 额外留了一个 `private` 列（默认不用）。以后你想把某条生日设成「只有我自己知道」，不用再做一次数据库迁移。

## 三、这一期的安全设计（以及为什么这样设计）

- **口令不再明文。** 库里只存 `pbkdf2_sha256$120000轮$盐$哈希`，明文口令不落库、不进镜像。
- **登录状态与口令解耦。** 会话签名密钥是首启随机生成的 `data/auth_secret.key`（权限 0600）。以前密钥直接从口令派生，意味着你给家人改个口令，全家都会被踢下线；现在改谁的口令只有那个人需要重登。
- **要一次性让所有人下线**（怀疑口令泄露时）：把 compose 里 `AUTH_EPOCH` 改个数字，重建容器，所有人的登录态立刻失效。
- **补上了三个越权口子**（这些在 v8.3 里其实就存在，只是那时只有一个用户没暴露）：
  - `DELETE /api/items/<id>` 原本不校验内容归属，拿到 id 就能删别人的笔记——现在删除前必须先按当前用户的可见范围确认。
  - `/api/attachments/<id>`、它的 `/thumb`、`/solidify`、删除附件，原本任何登录者拿到附件 id 就能读别人的 NAS 引用和缩略图——现在一律先校验所属条目可见。
  - 顺手修了 `delete_attachment` 的一个真 bug：它写的是 `WHERE item_id=?` 却传入附件 id，结果既删不掉目标附件，还可能连带删掉另一条内容的全部附件。
- **界面偏好按人存。** 原来 `ui_state` 是全局一行，你拖一下日历列宽，家人手机上也跟着变；现在键名带用户 id。
- **备份改在线快照。** WAL 模式下最新事务可能还在 `-wal` 里没并回主文件，`update.sh` 原来直接 `cp calnote.db`，那份备份可能少了最近几分钟的数据，真出事回滚就会丢笔记。现在优先用 SQLite 的 `VACUUM INTO` 出快照（宿主机有 `sqlite3` 就用，没有就走容器内 Python），两者都不可用时才退回拷贝并连带备份 `-wal`，同时提示你回滚要两份一起放回。
- **升级不会把自己锁在门外**：管理员账号直接由现有的 `AUTH_USER/AUTH_PASS` 转出来，你原来的口令继续有效。另外若这两个变量没配齐，v9 **一个账号都不建**、保持无登录状态——早先版本会随机生成口令只打在日志里，很容易把人关在外面，这条已经改掉了。
- 容器健康检查 `/api/health` 不要求登录（否则 Docker 会把正常容器判成不健康反复重启）；js/css/图标也放行，页面数据和所有 `/api/` 接口在墙内。

## 四、怎么升级

```bash
cd /vol3/1000/01资料/calnote
sh update.sh 日历便签-v9-多用户版.zip
```

`data/` 不动、不用重导数据。users 表、`owner_id`、`private` 这些新列都是启动时自动补的，老的 5000 多条内容会自动归到你（1 号主账号）名下——**所以升级后家人暂时看不到你的旧笔记，这正是「笔记私有」该有的表现**；共享的日程、生日、待办他们照常能看到。
