## 一、预算

「记账」面板顶部多了「设预算」，给某个分类填一个月度金额就行，例如「餐饮 1500」。

- 用到 **80% 标黄**、**超过 100% 标红**（阈值 `BUDGET_WARN_PCT` 可调），条子上同时显示「还剩多少 / 超了多少」。
- 底部有一条**预算合计**，所有分类的额度与已用汇总，同样两档标色。
- 预算按「分类 × 月份」独立存，10 月设的不影响 11 月；删预算只删额度，**不会碰任何流水**。
- 同一分类同一个月重复设置是覆盖，不会堆出两条。

## 二、图表

本月分类占比饼图 + 近 12 个月支出柱状图（蓝色那根是当前月），鼠标/手指按住一条能看到具体数字。

**全部是手写 SVG，零外部依赖**：不引 CDN、不打包 ECharts。你的 NAS 经常断外网或换域名，靠外部资源的话整块图表会白屏；现在两张图加起来只有几 KB，样式也跟现有 `style.css` 一致。数据不足时（比如只有 1 个分类）直接不画，不会画个半截图骗人。

## 三、导入导出

**导出**：面板「导出CSV」，列是 `日期,方向,金额,分类,账户,转入账户,备注,记账人`，带 BOM，Excel 直接打开不乱码；可以只导当前月，也可以导整本。文件名自带账本名和月份。

**导入**：面板「导入账单」，三种文件都能认（自动判格式，不用你选）：

| 来源 | 认这些列 |
| --- | --- |
| 微信账单 | 交易时间 / 交易类型 / 交易对方 / **金额(元)** / **当前状态** |
| 支付宝账单 | 交易时间 / 交易分类 / 交易对方 / 金额 / 交易状态 |
| 本应用导出 | 日期 / 方向 / 金额 / 分类 / 账户 / 转入账户 / 备注 |

判据特意选的是**各家独有的列名**——第一版我用过「收/付款方式」来分辨，结果微信和支付宝都有这一列，支付宝账单被判成了微信账单（测试抓出来的，已改）。文件前面那几行「微信支付账单明细 / 导出时间 / 分隔线」说明行会自动跳过，去找真正的表头行；编码 UTF-8 和 GB18030 都能读（支付宝下载的常是 GBK 系）。

**默认是预览，不动数据**：点「开始」先给你一份对账清单——识别成哪家、可导入几笔、重复跳过几笔、不适用跳过几笔、解析失败几笔，还有前 5 条样例和**每一行解析失败的原因**。你确认数字对了，再勾「直接写入」导第二次。

## 四、导入的口径（这些是我定的规则，看你是否认可）

- **金额一律 Decimal 解析成分**，不走浮点；`¥18.00`、`￥35.50`、`1,234.00` 都能吃。解析不出来的行**计数并报原文**，绝不静默当 0 或悄悄丢掉。
- **跳过不计入收支的行**：微信/支付宝里状态是「交易关闭」「已全额退款」「退款成功」「已退款」的，以及收/支为空或「/」「不计收入」那类本来就不该入账的行。
- **退款方向**：金额是支出但交易类型或状态里带「退款」的，按收入入账（不然会白记一笔支出）。
- **分类映射**：按关键词映射到你账本里已有的分类，例如「餐饮美食 / 外卖 / 快餐」→ 餐饮，「交通出行 / 打车 / 加油」→ 交通，「文化休闲 + 电影」→ 娱乐。映射不上的**归到「其他」，但把原始交易分类、交易对方、商品说明全部拼进备注**，信息不丢，回头你能自己改分类。
- **重复判定**：同账本 + 同日期 + 同金额 + 同方向 + 备注前 40 字相同 → 视为重复跳过。所以同一份账单导两次不会产生双份账；但**同一天两笔一模一样的开销会被合成一笔**——真遇到就在备注里加点区别（比如时间）。
- **账户**：账单里的「支付方式」（零钱 / 余额宝 / 花呗）和你自己的账户名不一定对得上，所以我**不自作主张映射**，导入时由你选一个目标账户统一记入。

如果你要的规则不一样（比如退款想按负支出记、或者想把「花呗」自动对应到你的信用卡账户），告诉我，改的是映射表和几行判断，不是重写。
