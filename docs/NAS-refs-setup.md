# v6.0 · NAS 文件引用（不上传、不占双份空间）

## 这一版解决什么

以前加图片/附件是**上传**：手机 4MB 原图 → 拷进 `data/attachments` → NAS 上等于存了两份；而且走飞牛域名时还会被反代的体积限制掐（那个 `保存失败：Failed to fetch`）。

现在改成**引用**：文件还在你自己的目录里，笔记里只存一条**指针**（例：`相片/2026/10/现场照片.jpg`），
- 加引用瞬间完成（没有任何上传动作）
- 不占额外空间（零副本）
- 不受文件大小限制（没有 POST 大 body 这回事）
- 点一下就内联预览（图/视频/音频/PDF），⤓ 才下载，「存一份」才会真复制进应用存储（可选，防原文件被删）

## 必做的一步：把目录挂进容器（三行）

**只有容器能看见的文件，才可能引用。** 这一步做一次就好。

### 方法 A：用本包里的 `docker-compose.yml`（推荐）

我已经把你给的三个目录写进去了：

```yaml
    volumes:
      - ./data:/app/data
      - /vol3/1000/01资料:/nas/资料:ro
      - /vol3/1000/相片:/nas/相片:ro
      - /vol4/@team/制造分厂:/nas/制造分厂:ro
    environment:
      - NAS_ROOTS=资料:/nas/资料,相片:/nas/相片,制造分厂:/nas/制造分厂
```

- 冒号**左边** = NAS 真实路径（飞牛文件管理里能看到的那个）
- 冒号**右边** = 容器里的路径（随便起名，但要和 `NAS_ROOTS` 对得上）
- 结尾 `:ro` = **只读**，这个应用永远改不了、删不了你的原始文件
- `NAS_ROOTS` 里的 `资料 / 相片 / 制造分厂` 就是选择器第一屏看到的三个来源名字，也是存进数据库的别名

改完在 NAS 上执行：

```bash
cd 这个目录
docker compose up -d      # 会重建容器并加载新挂载
```

### 方法 B：在飞牛 Docker 界面里加（不想用命令行）

1. Docker → 应用/容器 → 找到 `calnote` → **停止**
2. 编辑（或"重新创建"）→ 找 **卷 / 目录映射 / Volume** 这一栏
3. 添加三条：容器路径分别填 `/nas/资料`、`/nas/相片`、`/nas/制造分厂`；主机路径选对应的 `/vol3/1000/01资料`、`/vol3/1000/相片`、`/vol4/@team/制造分厂`；模式/权限都选 **只读 RO**（没有只读选项就用默认，应用本身只会读）
4. **环境变量** 那一栏加一条：`NAS_ROOTS = 资料:/nas/资料,相片:/nas/相片,制造分厂:/nas/制造分厂`
5. 保存 → 启动

### 验证挂载有没有生效（30 秒）

容器里执行：

```bash
docker exec -it calnote sh -c 'ls /nas; ls /nas/相片 | head'
```

能看到你的目录和文件就成；看不到就是主机路径写法不对（飞牛有时是 `/vol1/1000/...`，也可能需要你从文件管理里复制绝对路径），或者那台机器上 `/vol4/@team` 是团队盘、要先把团队盘挂载在容器可见的位置。
页面里的判断：点「📁 从NAS选」进来，如果某来源标着 **"未挂载"**，就是这一条路径没生效。

## 日常怎么用（笔记类型）

1. 新建/编辑笔记 → 附件那一行点 **📁 从NAS选**
2. 弹层里：三个来源 → 点进子目录（顶部「‹ 上层」回退，右上可切「只看图」，搜索只搜当前目录，大目录一次列 300 条并给"再加载"）
3. 点文件 = 打勾（可多选）→ 右下 **挂到这条笔记**
   - 还没保存的草稿：会先排队，点「完成」保存时一起挂上（提示会写清挂上几个、几个没挂上）
   - 已存在的笔记：立即挂上并刷新
4. 引用行长这样：`🖼 现场照片.jpg  4.1MB · 🔗2  ⤓  存一份  ✕`
   - 点整行 = 在线预览（图/视频/音频/PDF 内嵌，其它类型直接下载）
   - `🔗2` = 别的笔记也在引用同一个文件（**不会重复占空间**，删掉一条只是取消引用）
   - ⤓ = 下载；存一份 = 复制进 `data/attachments`（从此不怕原文件被删/改名）
   - ✕ = **只取消引用，绝对不动你 NAS 上的原始文件**（弹窗也是这么写的）
5. 原文件被移走/改名：引用行变黄 `⚠ 原文件不在`，抽屉里也能看总数（点它列清单）。找到新位置就删掉旧引用重新选，或点「存一份」把当下还能读到的版本留下。

## 几个你关心的细节

- **换盘 / 改挂载点不致命**：库里存的是 `别名/相对路径`。盘换了、容器路径变了，只改 `NAS_ROOTS` 那一行，旧笔记照样打开。
- **越权防护**：只能读 `NAS_ROOTS` 里那三个目录**之内**（含软链跳出去也拦，实测 `../../etc`、软链到 `/etc/passwd` 都是 403）。想加新来源，就在 compose 里加一行挂载 + 在 `NAS_ROOTS` 里加一项。
- **缩略图**：后端生成的真正小图（默认 160px，缓存 `data/thumbs`），首次打开生成一次，之后走缓存；超过 8000 张或 500MB 自动删最旧的。**`data/thumbs` 整目录删掉也没关系**，会自动重建 —— 它不是你的数据。
- **改了 Dockerfile（加了 Pillow）**：第一次部署要多等 20~60 秒装图像库；构建失败就把 `requirements.txt` 里 `Pillow==11.3.0` 改成 `Pillow`（不锁版本）或换国内源镜像，我也可以改成不依赖 Pillow 的模式（那时图片直接用原图缩放，占点流量但功能不缺）。
- **备份**：`data/` 里除了 `calnote.db`，现在还有 `attachments/`（只有你点过"存一份"或走上传的才在里面）和 `thumbs/`（可删）。导出 CSV 会带上引用路径，导回去引用能重建。
- **老功能一个没删**：`＋图片`（上传）、`📎文件`（上传）、附件删除、正文图片预览、复制文字/存为副本/删除三枚卡片小按钮、文件夹分组、生日年龄、正文吃满屏 + 键盘跟随，都还在。
