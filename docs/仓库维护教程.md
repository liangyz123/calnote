# 日历便签 · 仓库维护教程

> 仓库地址：`https://github.com/liangyz123/calnote`
> 这篇讲：目录里都有什么、改一处代码要走哪几步、怎么部署到飞牛、怎么回滚、哪些东西**绝对不能**进仓库。
> 看完能自己做：改文字/改样式/加字段/加接口/修 bug。

---

## 0. 一句话流程

```
改代码 → python3 tools/check.py（18 项全绿）→ git commit → git push
        → 在 NAS 上 git pull → docker compose up -d --build → 手机/网页重开
```

**自检不绿就别部署**，`check.py` 会用临时数据库跑接口，不碰你的真实笔记。

## 1. 目录里都有什么（改哪里 → 影响什么）

```
app.py                便签主程序：建表/迁移、登录、记录与附件、垃圾桶、天气、NAS 引用、界面偏好
ledger.py             记账模块：账本/账户/分类/流水/预算、记账垃圾桶、账单导入（含微信 xlsx）
vault.py              密码本模块
requirements.txt      Python 依赖（改这里 → 必须 --build，构建时 pip 安装）
Dockerfile            镜像怎么造（不要加 apt 安装大件，会卡十几分钟）
docker-compose.yml    端口、口令、NAS 只读挂载、保留天数等“运行时配置”
static/
  index.html          页面骨架（有哪些弹层、按钮的位置都在这）
  app.js              便签前端（日历、编辑框、附件、垃圾桶、可拖布局）
  ledger.js           记账前端（分段标签、卡片、图表）
  vault.js            密码本前端
  style.css           所有样式（列宽、宫格大小、字号、颜色）
  sw.js               Service Worker 缓存（改完前端 MUST 递增版本号，见 §4）
tools/
  check.py            仓库自检（本地一键体检）
  refresh_weather.py  天气重刷 CLI           build_calnote_import.py / nowen_extract.py / pull_attachments.py  一次性迁移工具
scripts/
  push-to-github.sh   第一次推仓库用
  make-fpk.sh         重新打“飞牛桌面图标”的 .fpk
docs/                 全部说明文档（README=技术说明、CHANGELOG=版本改动、各种专题）
fpk/calnote/          飞牛桌面入口应用的工程（manifest/cmd/图标）
update.sh             NAS 上一键更新 + 自动备份
```

三条经验规则：

| 想改的东西 | 去哪个文件 |
|---|---|
| 一句话、一个按钮文字 | `static/index.html` 或对应 `static/*.js` 里的模板字符串 |
| 大小、颜色、排版 | `static/style.css`（列宽/宫格在 `:root` 的 `--w-cal / --w-mid / --dh-fs` 和 `.lq-chip` 那几段） |
| 界面行为（点了发生什么） | `static/app.js`（便签）/ `static/ledger.js`（记账） |
| 数据、接口、权限 | `app.py` / `ledger.py`（记账） |
| 运行配置（端口、口令、挂载、保留天数） | `docker-compose.yml` |

## 2. 三种改法，按改动大小选

### A. 小改（改文字、改一个颜色）——网页上就能做

GitHub 网页 → 打开文件 → 铅笔图标「Edit」→ 写 commit message → `Commit changes`（选 main 分支）。
改完到 NAS 上：

```bash
cd /vol1/1000/docker/calnote
git pull
docker compose up -d --build        # 只改了前端也要重建镜像，见 §4
```

### B. 正常改（加字段、修逻辑）——本地 git（推荐）

电脑上装好 git 后：

```bash
git clone https://github.com/liangyz123/calnote.git
cd calnote
python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 改代码…
python3 tools/check.py                                    # 必须全绿

git status                        # 只应该看到你改的文件
git add static/ledger.js
git commit -m "记账：分类卡片支持删除并立即刷新列表"
git push
```

再到 NAS 上 `git pull && docker compose up -d --build`。

> 想在电脑上"跑了看"再提交：`AUTH_USER=admin AUTH_PASS=随便填一个 python3 app.py     # 临时库，本地随便`
> 然后开 `http://127.0.0.1:8000`（用的是仓库里的空库，不碰 NAS 数据）。

### C. 顺手在 NAS 上改了代码——一定要回传仓库

NAS 上直接改了文件（比如应急修 bug）之后：

```bash
cd /vol1/1000/docker/calnote
git status && git add -A
git commit -m "应急：xxx"
git push
```

**不回传就是埋雷**：下次你在别处 `git pull` + `--build`，NAS 上那个手工改动会被无声覆盖。这条是仓库维护里最常见的丢代码原因。

## 3. 每次改动的固定动作（背下来）

1. **先看一眼 `git status`**，确认工作区干净，不要在不认识的改动上继续叠。
2. 改完 `python3 tools/check.py` → 全绿。
3. 前端文件（`static/*`）有改动 → **必须递增版本号**（§4）。
4. `git commit`：一次只讲一件事，中文写清"改了什么 + 为什么"。例：
   - `记账：修掉删掉主区下拉后遗留的 onchange 空引用（导致整块不渲染）`
   - `天气：今天的实测值每日自动覆盖一次，历史用档案库`
5. `git push` → NAS `git pull` → `docker compose up -d --build` → 手机重开验证。
6. **顺手**：`bash update.sh`（会先备份数据库）——或者每月至少备份一次 `data/`。

---

## 4. 版本号必须递增的唯一原因：Service Worker

前端 JS/CSS 是被 `static/sw.js` 缓存在手机/电脑上的。缓存名不变，你改了也可能**看不到任何变化**，会误判成"代码没生效 / 又 bug 了"。

改完这些文件之一：`static/*.js`、`static/style.css`、`static/index.html`，就打开 `static/sw.js` 改一处：

```js
const CACHE = 'calnote-v10.5';     // ← 尾号 +1（v10.5 → v10.6）
```

顺带建议：改 `static/app.js` 顶部那行版本注释、`app.py` 里那份内联版本串（如果有），三处同名，方便以后定位是哪一版。

部署后手机如果还像老样子：**关掉便签后台再开**；再不行就在浏览器里清一次站点缓存（网页版：F12 → Application → Service Workers → Unregister + Clear site data）。

## 5. 数据、口令、绝对不进仓库的东西

`.gitignore` 已经挡住：`data/`、`*.db*`、`*.log`、`nohup.out`、`__pycache__/`、实验目录 `exp/`、编辑器杂物。

要额外自律的：

- **不要把 `docker-compose.yml` 里你的真实口令、外网域名换成明文提交**——建议改成读环境文件：
  ```yaml
  environment:
    - AUTH_USER=${CAL_USER}
    - AUTH_PASS=${CAL_PASS}
  ```
  NAS 上放一个 `.env`（写 `.gitignore` 里，永不提交）：`CAL_USER=admin` / `CAL_PASS=你的口令`。
  已经提交过的口令，**改一次口令**并把这条记录的 commit 洗掉（`git log -p -- docker-compose.yml` 自查）。
- `data/calnote.db`、`data/attachments/*`、`data/weather_cache.json` 是**你的人生数据**，仓库里没有也不需要。备份走 `update.sh` 或整目录拷贝。
- 想传样本（微信/支付宝账单）来调试列映射时，**先删掉金额和单号**再放进仓库；或者只放到聊天里，不进 git。

## 6. 分支与提交规范（一个人用也要，好处是能对比坏在哪）

```
main   已部署、已知能跑            ← NAS 只跟这条
dev    平时改的地方                ← 改完自检通过再合并进 main
```

```bash
git checkout -b dev                # 一次性
git checkout dev                   # 日常
git push -u origin dev
# 自检 + 部署验证通过后：
git checkout main && git merge dev && git push origin main
```

NAS 上永远 `git checkout main && git pull`，就不会把半成品拉去部署。

## 7. 出问题怎么回滚

**代码回滚**

```bash
git log --oneline -10
git diff HEAD~1 HEAD -- static/ledger.js      # 看清楚最后一次改了什么
git revert HEAD            # 生成一个“反做”提交（安全，历史保留）
git push
```
NAS：`git pull && docker compose up -d --build`。

**只回到某个旧版本试**（不改历史）：`git checkout 58a781b -- static/ledger.js`（把某文件换成旧版）→ 自检 → 需要就用 `git revert` 正式落进历史。

**误提交/漏提交看这三条**：

```bash
git status --short          # 未提交的改动
git log --stat -1           # 刚才那次提交动了哪些文件
git ls-files | grep -E "\.db$|data/"   # 应该没有输出（有就是数据被跟踪了，要 git rm --cached）
```

**容器回滚**（代码没问题但起不来）：`bash update.sh 旧的代码包.zip` 会备份数据库并回滚镜像；或 `docker compose logs calnote --tail 50` 把错误行发给我。

## 8. 加一个小功能的完整样板（照抄就会）

以"给账户加一个备注字段"为例，前后端各要动什么：

1. **建表/迁移**（`ledger.py` `register()` 里 `init_ledger_db`）
   ```python
   # 老库升级：没有这一列就补上（新库靠 DDL）
   if "note" not in [x[1] for x in conn.execute("PRAGMA table_info(account)")]:
       conn.execute("ALTER TABLE account ADD COLUMN note TEXT DEFAULT ''")
   ```
2. **接口**：新建/改名接口的 `data.get("note")` 分支 + 返回体带上 `"note"`。
3. **权限**：能改的先过 `can_book(conn, current_uid(), book_id)`（这是防越权的那道，别绕）。
4. **前端**：卡片 `ledAsk('账户「x」', [..., { id:'note', label:'备注', value:a.note||'' }], cb)`。
5. **改完数据要刷新**：走 `ledChanged(段名, 提示语)`，别只 `ledLoad()`——否则界面上看不到变化，就像我们上一轮踩的那样。
6. `python3 tools/check.py` 全绿 → 提交时把新接口的冒烟项**加进 `tools/check.py`**（照抄现成两行 `call(...)` 的写法就行），以后谁改坏都有人挡。

## 9. 界面偏好、垃圾桶保留天数这类"可调项"

- 三栏宽度 / 当天标题字号：手机上拖不动，是刻意的；网页版拖分隔条调，存在服务器 `ui_state` 表，所以换浏览器/换电脑一致。想改默认值：`static/ledger.js` 里 `LAYOUT_DEF = { cal: 452, mid: 452, fsHead: 14 }`。
- 删除保留天数：`docker-compose.yml` 的 `- TRASH_KEEP_DAYS=30`（便签、记账同一套）。
- 记账分段哪几页/预算页是否显示：`static/ledger.js` 的 `LED_TABS` / `LED_TAB_HIDE`。

## 10. 飞牛 App 里点桌面打不开时（.fpk 那个图标）

1. 先分清是"端口没转发"还是"应用问题"：手机**浏览器**里开 `http://<NAS内网IP>:8000`（家里 WiFi 下）。打不开 → 不是便签的事，是 8000 没进飞牛的远程通道（去 设置 → 远程访问/Connect 把 8000 加上，或用你已经有的 https 域名）。
2. 图标地址写在 `fpk/calnote/app/ui/config`（`port` / `protocol` / `url`）。改完重新打包：
   ```bash
   bash scripts/make-fpk.sh          # 产出 dist/calnote.fpk
   ```
   然后**先卸载旧的 calnote 应用**再手动安装新的（不卸载，桌面还缓存着老地址）。
3. 顺手把 `fpk/calnote/conf/portal.conf`（跳转地址）也一起提交，以后照着它就能改。

## 11. 常用命令小抄

```bash
# 本地看改动
git status -s && git diff -U2

# 服务器上排查
docker compose ps
docker compose logs --tail=60 calnote
sqlite3 data/calnote.db "select count(*), sum(deleted_at!='') from items;"   # 总数 / 桶内数

# 一次性自检 + 部署演练
python3 tools/check.py
bash update.sh /root/calnote-v10.6.zip
```

有报错就三样东西发我：**Console 第一行红字**、`docker compose logs` 的关键几行、`git status` 输出。有这三样，基本都能一次定位。
